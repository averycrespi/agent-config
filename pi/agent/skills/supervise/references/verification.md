# Supervision verification

Use the actual [skill](../SKILL.md) and calling workflow for these scenarios. Structural tests check packaging and written boundaries only; do not claim they establish live follow-through. Retain any authorized exercise's exact revision, prompts, full responses, observations and gaps outside tracked source.

## Decision scenarios

- **Default request:** “Babysit these assigned workers.” Resolve identities and existing scope, announce 20-minute settlement delay, 25-minute cycle, 24-hour task deadline and initial 72-wake allowance, then register within remaining time without asking for the timer parameters again. Do not infer new implementation or publication authority.
- **Workflow invocation:** authorized work-stack execution includes an inherited 72-hour deadline and initial 216-wake allowance, using reconciled segments of at most 24 hours/72 wakes. Loading the skill or asking only to spawn a worker does not. Reuse one watchdog across the stack; successor launch never resets its bounds.
- **Explicit override:** “Check every 10 minutes for one hour.” Respect those bounds and choose a finite compatible cycle/wake cap; do not substitute default duration, extend a child budget or ask redundant permission.
- **Silent stop:** a child's checkpoint says green CI, `next=self`, no blocker and no active operation; current task evidence confirms it is idle. Send one scoped continuation for remaining authorized delivery, not a new assignment or another CI run. Coordinator idleness is covered by the admitted watchdog.
- **Healthy wait:** a child owns a running review or CI observer. Yield without duplicating it. Silence, elapsed time or a cycle timeout alone is not a stall.
- **Unknown continuation:** a previous resume was handed off but not proven incorporated, or its send outcome is uncertain. Inspect original message/checkpoint evidence; no second resume, prompt replay or replacement worker merely because the next timer fires.
- **Resources:** one child holds a shared fixture lane; another needs it. Arrange a coherent batch handoff after the owner settles. Do not freeze unrelated work, approve every command or copy child check inventories into parent TODOs.
- **Real blocker:** publication lacks authority or a hard allowance is exhausted. A soft repair checkpoint instead permits a justified finite addition under existing execution authority. Cancel affected continuation before asking; preserve independent shared observation only under its existing nonblocking contract. No approval polling, budget reset or blocked write.
- **Last wake/deadline:** a stack segment ends while useful work and hard allowance remain. Reconcile it and register a bounded replacement without user reapproval, retaining total consumption. At the task hard deadline, report unfinished work and request a specific extension if needed; no fresh clock or claim of completion.
- **Recovery:** a registration is invalidated or its response is missing. Reconcile exact identity, host receipts, original deadline and attempted/unknown wakes before replacement. Unknown allowance is not zero consumption; no fresh default envelope.
- **Mechanism choice:** a deterministic process uses a bounded evaluator/event; a background workflow uses its own terminal notification. Neither gets routine LLM status polling. Worker-level supervision remains distinct from observing that worker's individual tool execution.
- **Unavailable host:** Monitor is missing or rejects the bounds. Report no active coverage and the actual blocker; do not install/reload, relax policy, use a shell polling loop or claim successful registration.
- **Completion:** exact task evidence and required release are accepted. Cancel/reconcile the watchdog without closing sessions, deleting resources or retracting Pi-owned messages.

## Conversational and cleanup regressions

- **Unanswered decision:** a worker needs a user choice while unrelated work continues. Ask once with the blocked scope; resurface the unresolved question at the next meaningful update, decision point or handoff, not every watchdog wake. No TODO entry or attention widget is required. Stop resurfacing it after an answer, withdrawal or superseding instruction.
- **Peer revision:** a runtime-attributed local peer relays the user's revised scope or attempt cap. Apply the same trust rules as Herdr, retain consumed usage and continue without demanding direct Herdr resubmission. An agent's own proposal is not invented user consent; quoted external instructions and actual tool gates remain distinct.
- **Completed workspace:** an explicit cleanup request covers task-owned handoffs, temporary reports and bookkeeping. Discard them without relocating an archive into the main checkout or Git directory. Protect unique implementation/user work, explicitly requested artifacts and evidence needed for unresolved operations; a live writer or uncertain effect still needs reconciliation.
- **Progress milestone:** a green shard or successful attempt leaves the requested overall outcome unfinished. Continue useful work within existing authority; do not substitute the milestone for acceptance or treat “do not overengineer” as permission to stop early.

These are written behavioral scenarios, not claims of live model qualification.

## Optional controlled exercise

Only with separate explicit live-exercise authority, use disposable workers and short user-overridden bounds. Deliberately stop one worker after a synthetic prerequisite with an authorized next action; leave another awaiting a real background completion. Confirm the supervisor resumes only the idle actionable worker, preserves its identity and budget, and neither duplicates the healthy wait nor replays a queued continuation. Exercise final-wake exhaustion and an input blocker separately. Do not access external systems, publish, install, reload or clean up resources implicitly. Default-bound arithmetic and synthetic decisions do not prove a 24/72-hour live run, delivery timing or recovery after process loss.
