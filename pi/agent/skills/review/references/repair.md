# Authorized Review Repair

Read completely before a repair batch. Follow [review](../SKILL.md): retain the full authoritative report and present its findings before editing. Repair requires existing user/task authority or explicit approval; material scope changes still need authorization.

Use the calling task's repair budget and continuity mechanism; do not impose another workflow's storage or lifecycle. For standalone review-and-fix requests, default to two authorized repair batches and retain consumption and the original report in existing task continuity. Preserve consumption across interruption. If recovery evidence is unavailable, reconcile the allowance with the caller rather than assume a fresh budget. Do not create a new orchestration system or require a new request for each already-authorized batch. Confirmation alone consumes no edit batch; ordinary implementation/test iteration is not review repair.

Repair consolidated blockers only within authorized scope, in the owning session. Rerun affected and repository-required checks, then invoke `reviewMode: confirmation` using [the input contract](workflow-input.md) with earlier blockers/report, dispositions, changed revision, and repair-touched boundaries. Confirmation checks original blockers, affected boundaries, and repair-induced regressions—not unrelated fresh improvements. Expanded scope or uncovered requirements require a new `initial` review against updated coverage; a boundary label alone does not require duplicate review. Preserve unresolved findings. At the recorded allowance, stop with remaining blockers and a concrete next action for the caller. Exhaustion never means approval. The caller owns additional allowances and accepted exceptions; neither changes the authoritative report or makes failed evidence pass.
