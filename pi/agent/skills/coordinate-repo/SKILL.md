# Coordinate Repo

Own one human-facing coordination index, not the workers' execution ledgers. Coordinate independent/general assignments concurrently through existing Herdr, Background and task workflows. Keep short inline questions inline; use short-lived read-only helpers for bounded reasoning, not as persistent task owners. For an ordered series of stacked tickets, route to [work-stack](../work-stack/SKILL.md): retain its entry point, serial ordering and existing recovery records. Do not adopt, migrate, retire, or concurrently control an existing stack or unrelated session. Use [spin-out](../spin-out/SKILL.md) for a standalone launch without managed coordination.

## Establish scoped authority

Read repository instructions, existing [index](references/index.md), relevant handoffs and child checkpoints before acting. Resolve repository/common-directory identity, exact reachable source, current coordinator/worker identities and competing writers. Entering this mode or discussing an idea grants no arbitrary execution authority. Record the user's operating agreement once: delegated assignment scope, completion boundaries, excluded actions, optional resource budgets, finite supervision authority and durable instruction reference. Ask only about material ambiguity; investigate answerable uncertainty first.

Separate delegation from execution and publication/destructive authority. A covering delegation allowance permits launches without per-launch approval, but each brief must state its actual implementation/commit/publication authority. Never infer permission for merges, installations, Stow, live reload, cleanup, unrelated sessions or external changes. One writer per checkout; the coordinator never edits an active child's checkout or claims its ticket checkpoint. Ticket workers own [work-ticket](../work-ticket/SKILL.md) through the assigned boundary; generic tasks use proportionate criteria and their existing local task record.

Do not impose a fixed/default worker ceiling or aim to fill capacity. Admit independent authorized work according to actual resources, supervision coverage and explicit user budgets. Identify shared contracts before parallelizing coupled work; agree the contract or keep one owner/serial dependency. Separate worktrees do not isolate services, ports, databases or external mutations. Constrain those resources when used; do not require containers or a scheduler for every assignment. A blocker or uncertain effect blocks its affected scope, not automatically unrelated assignments. Report concrete queue reasons, including actual host capacity, rather than invented concurrency policy.

## Assign and supervise

1. Read the [shared launch procedure](../spin-out/references/launch.md) completely and load [Herdr](../herdr/SKILL.md). Reuse exact-base selection, ignored self-contained handoff/readback, identity checks, startup, attention-before-submission and execution confirmation. Required source unavailable in the checkout blocks launch; never silently substitute a moving tip.
2. Allocate a stable assignment ID and revision. Its brief owns goal/criteria, task-specific authority/exclusions, checkout/base and reporting paths. Include parent identity/index, existing child checkpoint path and readable role/workflow references. A materially changed assignment needs a new revision and acknowledged scope, not silent reassignment.
3. Read [managed decisions](../spin-out/references/decisions.md); enable parent mode only in managed child processes. Require its available implementation before launch. Standalone and ordinary interactive defaults stay unchanged.
4. Follow [supervision](references/supervision.md): shared bounded groups, exact membership, before-effect intent, host receipts, gap reconciliation and mechanically retained parent accounting. Register coverage before initial/continuation submission. An active matching observer needs no replacement. End the turn while pending; no model-turn polling or detached-supervision claims.
5. On attention reconcile every affected member's durable coordination state, even when only one signal arrived. Keep small last-observed disposition/question/next summaries in the index if useful, explicitly derived. Revalidate before control/acceptance; do not transcribe routine progress, check inventories or child CI/repair budgets. Status with unchanged facts writes nothing.

## Decisions, pause and intervention

Use the shared protocol's **nonblocking human interaction** for managed questions: announce each request once with a reply handle in ordinary conversation, retain its child-owned full correlation, and keep independent work observable. Do not call modal ask-user for those routed questions or poll for approval. Two pending human questions must not prevent accepting a third worker's qualified result. Actual runtime approvals remain actual approval gates, not messages to reinterpret.

Answer only from established evidence/delegated authority, honestly labelled as a parent decision, or from an actual correlated human instruction. Stale, ambiguous, cancelled and unanswered requests remain blocked. A human reply does not replenish any allowance. Record continuation intent before one prompt to the same owner and resolve it only after matching application evidence; never replay uncertainty.

For pause/intervention, identify affected assignments, authority and shared resources. Persist control intent before any authorized communication; distinguish requested pause, submission, acknowledgment and quiescence. Reconcile checkpoints, in-flight effects and further-write disposition before reporting a worker paused. Do not remotely answer an unexpected UI or kill a worker to manufacture quiescence. Unrelated assignments continue only inside their retained authority; an explicit project-wide pause stops new launches/control until reconciled. Direct human intervention must be correlated back to current child state, not overwritten by an older parent answer.

## Accept results, not settlement

Match assignment/revision and exact result revision/boundary to the brief. Read referenced required evidence and check coverage, failures/exceptions, pending effects and owner/further-write disposition. Runtime settlement, notification, a green label or a child claim alone never completes an assignment. An incomplete result stays offered, not accepted. Require released ownership or explicit no-further-writes quiescence before integration/reassignment; evidence acceptance does not itself release a writer.

Reuse valid child tests and independent review. Do not routinely rerun work-ticket delivery, mirror CI observation, commission duplicate review or read all completed history. Deepen verification only for changed state, missing/stale/inconsistent/failed evidence, unresolved risks or explicit gates. Record accepted exact revision plus evidence/release references and honest exceptions. Acceptance is not integration: serialize any separately authorized integration and check the combined state. Independently green branches do not prove their combination. No implicit merge, retarget, restack or publication.

## Recover and hand over

Read [recovery](references/recovery.md) before resuming or transferring coordination. Establish explicit takeover authority and the former coordinator's relinquishment or proven inactivity before control. Preserve child owners, pending questions/effects and consumed supervision allowances. Restore bounded observation only after reconciliation; never relaunch a missing-looking worker or resend an uncertain prompt. Corrupt/conflicting ownership stops affected actions while retaining resources. This is procedural ownership, not hard fencing or automatic failover.

Before stopping, update only changed coordination facts and name status, evidence/blocker, next actor and action. Retain durable references before compacting detail. Use the [verification and live recipe](references/verification.md); deterministic fixtures and structural checks do not prove model compliance.
