# Shared bounded supervision

Use [Monitor](../../../extensions/monitor/README.md) as the sole scheduler and [mailbox](../../../extensions/mailbox/README.md#events-and-batching) as durable report storage. Discover actual Script/Monitor schemas. Provider permission is not authority. One mailbox subscription covers many explicit assignments; do not create one observer per worker or revive session-event transport.

## Membership and catch-up

Use one logical mailbox watcher per coordinator for its shared inbox. Scope its evaluator and continuation instructions to the mailbox and durable project-record path, not a fixed worker list. Retain current assignment/revision/worker/checkpoint identities in that record and resolve them on attention. A watcher is notification coverage, not an authorization boundary: validate each report against current assignment identity and authority before acting.

Keep an active matching mailbox watcher when assignments are added, removed or revised. Persist the membership change and the new worker's coverage under its existing observer ID before prompting; do not cancel/recreate the watcher solely to change membership. Retain the registration-time membership snapshot as historical receipt provenance, not a frozen admission list. If an existing watcher has hard-coded worker scope, reconcile and replace it once with mailbox-scoped instructions; never pretend its immutable instructions changed.

Subscribe to `mailbox.changed` and poll the same inbox with the initial evaluator. Events contain only address hints; list supplies retained messages even before subscription, during registration gaps, after restart and after lost notifications. Do not claim notifications themselves are durable.

Use the [recurring mailbox recipe](../../../extensions/mailbox/README.md#events-and-batching): new reports qualify by count or oldest-new age; covered but unacknowledged reports qualify again only after the longer reminder interval. Defaults are 3 reports, 60 seconds and 5 minutes; explicit immutable per-observer fields override defaults, with validated ranges and no ambient environment override. Empty inboxes never satisfy age. Monitor's independent timeout is attention, not a batch or task failure. Select `recurring: true` and explicit finite lifetime/wake limits from the existing allowance. Evaluators call read-only `mailbox.observe` with committed `state`: no ACK, project-state writes, question handling or Herdr control. Keep the recipe's persist-before-ACK instructions on every wake.

On attention reconcile the exact receipt, then drain bounded pages. Apply the [shared report protocol](../../spin-out/references/decisions.md): validate identity and evidence, persist changed coordination facts and incorporated report IDs, then ack. Do not postpone an unrelated qualified result because questions are pending. Start a fresh scan after cursor exhaustion to catch new arrivals; bound each processing pass and retain next action for remaining work. ACK means recorded, not answered, accepted or completed; ACK safely recorded questions even when waiting for humans. Unacknowledged reports remain reminder-eligible within the original bounds. Normal handling requires no cancel/re-registration: retain the recurring observer and its accounting reservation; Monitor rearms after positive message admission and correlated settlement. Attention may coalesce during handling, and an ACK cannot retract already queued attention. Unknown/unattributed messages require reconciliation rather than a replacement loop.

No reports is not failure. Routine progress remains in child checkpoints. End the model turn while observing; no repeated model-turn reads, sleeps, approval polling, automatic restart or reassignment. Before registration replacement, reconcile the exact owned prior observer, its pending/uncertain handoff and retained accounting. Restoration is receipts only; absence from a different session inventory does not prove an old job inactive. Never cancel unrelated jobs.

## Wellness without session monitoring

Use the mailbox for worker-owned questions, blockers, results and answer confirmations. Add per-agent observation only for a concrete signal the reporting path cannot supply, such as process exit, an actual runtime approval wait or suspected stale progress. Discover supported event schemas first; do not invent an event transport or open one Monitor job per agent by default. Multiplex supported signals where practical without coupling ordinary membership changes to replacement of the stable mailbox watcher. Otherwise use a separately accounted, bounded read-only observation for the specific need. Signals request reconciliation, never acceptance, automatic answers, restarts or approval polling. Keep CI observation with the implementation worker; do not duplicate it in the coordinator.

Choose a quiet interval and checkpoint-staleness threshold appropriate to the assignment in the operating agreement; no mandatory heartbeats. After that interval, a bounded Monitor evaluator may inspect explicit workers through the existing selected [builtins Script surface](../../../extensions/builtins/README.md#script-provider). Use `builtins.bash` for already-inspected read-only `herdr pane process-info --pane <exact-pane>` and checkpoint `stat`/Node filesystem metadata commands. Pin/quote exact paths and identities in the source; never execute report text as a command. Inspect the installed Herdr command/output schema before constructing the evaluator, check its actual result envelope, and reject truncated, malformed or identity-mismatched output. Do not assume shell permissions, presence of a PID or runtime idleness proves worker identity/health.

Inspect process liveness **and** checkpoint freshness before requesting wellness condition attention. Correlate the launch process identity/creation evidence with the current occupant. `healthy-quiet` (live matching process, fresh checkpoint) waits. Proven exit, a stale checkpoint after the quiet interval, or unknown identity requests one reconciliation—not a restart, reassignment or assertion of failure. Staleness can mean long legitimate work. `scripts/reports.js` exports the pure `wellness` classifier for these explicit observations; it cannot establish their truth. Combine wellness and mailbox reads in one evaluator when within call/output bounds, or use one separately accounted bounded read-only job. Keep routine healthy observations out of model turns; timeout still has independent Monitor semantics.

## Shared accounting, separate from child budgets

Select finite supervision authority once. For a new agreement without narrower limits use eight hours from first registration and 40 cumulative wake attempts across the project, not per worker. Answers, new heads, worker changes, replacement and handover do not reset them. A serial stack uses the same mechanics and its declared stack allowance. Child CI and repair budgets remain child-owned.

Use `scripts/supervision.js` for arithmetic, storing its returned JSON once in the project record's Observation section. It performs no effects or scheduling. Initialize with `{action: "init", deadline, maxAttempts}`; subsequent CLI calls accept `{current, operation}`. Use host timestamps and actual receipts, not estimated subtraction. Read and update Observation through the [canonical index helper](index.md#confirm-before-effects), preserving every other section. Require validated response identity/path/base/digest and independent readback before registration/control effects; successful arithmetic or exit zero is not durable persistence.

1. `reserve`: stable group (normally the mailbox), exact member identity strings at registration and durable pre-effect reference. For recurring coverage supply `recurring: true` and `maxWakes` (1–100, no greater than the remaining shared allowance). Reserve that entire cap until terminal reconciliation so another group cannot spend it; defaults remain one-shot/one wake for legacy callers. Persist returned pending reservation/bounds before registration. Retain original call arguments/source by reference. The helper's `members` is a historical snapshot; later membership and coverage changes belong in the project record without editing that reservation or resetting allowances.
2. Start using the reserved recurrence/wake cap and no more than returned clocks or remaining absolute deadline. `attach` takes the same group and actual host receipt; correlate against the originating call, not its display name. Terminal-before-attachment receipts are valid.
3. On attention inspect the exact receipt and handle retained reports, but keep a useful active recurring observer and its reservation. At completion, failure, exhaustion or an authorized replacement, cancel/reconcile any still-active observer or pending extension-owned attention first. `reconcile` takes the exact inactive terminal receipt and durable reference; charge its cumulative `wakes` once (including uncertain attempts), never once per child. Duplicate identical reconciliation is a no-op. Preserve uncertainty separately from arithmetic; a handoff is not handling or ACK.
4. An uncertain registration remains reserved until actual host evidence resolves it. No reset/recover-by-assertion/replay exists. At deadline or wake exhaustion reconcile once and stop observation with next actor/action; do not terminate children, renew budgets or infer completion. Explicit additive user authority is required to extend allowances.

Host capacity remains four occupied Monitor jobs with its existing event/call limits. Queue with the actual resource restriction; do not raise limits or cancel unrelated observers. A missing selected provider blocks unattended observation, not authorization for implicit installation or model-turn polling.

## Legacy one-shot transition

Existing one-shot registrations, stored reservations without recurrence fields, and the managed launch-helper coverage contract remain supported as one-wake reservations. Keep those running assignments under their original authority and helpers; no automatic migration or candidate installation/reload. On a separately authorized new registration after exact old-job reconciliation, callers with the new provider may reserve recurring coverage using the same accounting record and remaining bounds. Do not hand a recurring receipt to a legacy launch helper that requires one-shot coverage; retain its bounded one-shot path until that caller is deliberately updated. Never run both for the same inbox. Unrelated work-ticket CI remains one-shot and unchanged.

## Questions do not globally stop observation

Cancel/reconcile continuation for input-blocked work. Bounded read-only observation of independent assignments may continue under the [nonblocking interaction contract](../../spin-out/references/decisions.md#nonblocking-human-interaction). Never use it to resume unanswered work or poll approval. If no useful independent observation remains, cancel/reconcile and retain pending questions without repeatedly waking.
