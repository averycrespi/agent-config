# Shared bounded supervision

Read [Background](../../../extensions/background/README.md) and discover actual Script and Background provider schemas. Provider permission is not observation authority. Use existing `sessions.lifecycle` exact-incarnation subscriptions; keep settlement/input/shutdown filters. Parent-managed ask-user produces no input events: the child durably checkpoints its request before settlement. Notifications carry safe identity/disposition, never question contents or transcript data.

## Membership and coverage

Group independent workers into immutable one-shot jobs within **actual** host capacity. Background currently allows four subscriptions per job and four occupied jobs, including setup, cleanup and pending attention. Five worker identities need two groups (4+1), not five jobs. These are host safeguards, not a fixed/default product worker ceiling or a reason to fill capacity. Discover occupied slots; never cancel unrelated jobs. Queue a launch only with its concrete resource/coverage restriction, explicit user budget or dependency. Do not claim unlimited resources, raise constants, or silently run unsupervised assignments. When capacity is unavailable, report affected work and next action; human-scoped observation or a separately validated bounded checkpoint-polling strategy requires an explicit agreement, not model-turn polling.

For each group retain ordered assignment/revision/session/incarnation membership and corresponding receipt coverage references in the index. Event selection index maps to that immutable membership only. Missing attribution must not be guessed. Receipt coverage begins at target subscription ACK boundary, not launch/discovery. Inspect every affected member's durable state on shared attention, timeout or coverage failure, even if only one event was delivered: one-shot termination clears subsequent events and is not a durable inbox.

- **Join:** reconcile owner/checkpoint and current state, reserve registration intent, register a free group or replace an affected immutable group, bind receipt/coverage, then reconcile all new members once after ACK before initial submission. Never regard a pre-registration event as covered.
- **Exit/decision block:** membership removal never releases implementation ownership. Reconcile effects/receipt and remaining members before replacing the affected group; retain accepted or blocked assignment by reference. Do not disturb unrelated groups unnecessarily.
- **Disconnect/incarnation change/overflow:** the whole group's coverage is lost. Read every covered checkpoint and current identity, retain the gap/adverse receipt, and resolve disconnect or replacement before restoration. Preserve independent groups. Overflow is failure, not latest-event coalescing.
- **Replacement:** first cancel/reconcile the exact owned prior job and pending handoff; record its gap and retained allowance, then create a new immutable registration. Reconcile changed state both before and once after coverage ACK. No reconnect/replay claims.
- **Shutdown/reload/navigation:** observation is invalidated; restoration supplies receipts only. A new session cannot infer absence of the originating job from its own inventory. Recover original receipts and authority before any replacement.

An active matching job needs no replacement. End the parent turn while known work is pending. No repeated model reads, sleeps, lifecycle polling, approval polling, detached supervision or recurring-mutation inference. Events, expiration and runtime settlement are never acceptance evidence.

## Shared accounting, separate from child budgets

Select an explicit finite parent supervision policy in the operating agreement. For a new agreement without narrower limits use eight hours from the first registration and 40 cumulative one-shot wake attempts **across all groups**, not per worker. Preserve existing policies/consumption on resume. An answer, new worker/head, group replacement or handover does not reset them. Exhaustion ends parent observation, not child authority or child-owned CI. Reconcile once and report next actor/action; extending needs actual additive user authority.

Use `scripts/supervision.js` for caller-owned arithmetic; it performs no effects or scheduling. Store its returned object once as JSON in the index's Observation section. Import `allowance(deadline, maxAttempts)` only at initial agreement and `supervision(current, operation)` thereafter. Default clock is host `Date.now()`. It never mutates input and returns no child-budget changes. The same file is a CLI: `node <absolute-skill-path>/scripts/supervision.js` reads quoted JSON on stdin. Initialization uses `{action: "init", deadline, maxAttempts}`; subsequent calls use `{current, operation}` and return `{result}` for the single retained Observation value. Use actual host timestamps and preserved state, not invented counters. This CLI does not persist; combine its output with other changed facts in one index update at the safe boundary.

1. `reserve`: supply stable `group`, ordered exact member identity strings and durable pre-effect `reference`. It reserves one attempt and calculates `pending.cycleMs` (≤25 minutes) and `pending.lifetimeMs` (≤remaining absolute deadline and default host ceiling). Persist with launch/registration intent before calling Background. Keep the intent source/arguments in an exact retained session/tool reference.
2. Start one-shot with returned bounds and `max_wakes: 1`, no evaluator required. Bind the host receipt with `attach`, same group and `receipt`. Validate source-independent identity against the originating call, not display name. Persist ID/coverage references. Attachment also accepts terminal-before-attachment receipts.
3. On attention, inspect full receipt and all affected members. Cancel any still-active job/pending extension-owned attention before replacing or stopping. `reconcile` takes that exact terminal `receipt` and durable `reference`, adds host `wakes` once and clears the reservation. One shared wake charges one parent attempt, **not every member's execution/CI budget**. Identical duplicate receipt reconciliation is a no-op; unrelated/changed duplicates reject. Keep original receipts outside the snapshot, referenced by the current accounting anchor, not copied wake histories.
4. A registration with uncertain effect stays reserved until its exact receipt or authoritative absence/inactivity evidence is recovered. The helper deliberately has no reset/replay/recover-by-assertion command. If a receipt is unavailable, retain the reservation conservatively and resolve the control uncertainty with the operator; do not start a duplicate. Known attempted/unknown handoffs count as host attempts, never zero. Handoff is not consumption; reconcile its uncertainty separately from arithmetic.

The helper cannot verify receipt authenticity, authority or membership truth: read originating host evidence and the index before calling it. Its narrow mechanics do not enforce task state. Retain current group anchors plus durable historical evidence references before replacement; no model-authored budget subtraction. Child checkpoints independently own their repair/CI accounting.

## Questions do not globally stop observation

Cancel/reconcile continuation for work blocked on input. An explicitly authorized shared **read-only observation** job can retain independent-member coverage while questions await ordinary correlated human messages; its attention contract must only reconcile state and never auto-continue blocked writes. This is the [shared nonblocking interaction contract](../../spin-out/references/decisions.md#nonblocking-human-interaction), not a bypass of modal waits or approval gates. If no useful independent observation remains, cancel/reconcile and retain requests without repeatedly waking to ask again.
