## Early feasibility gate

Before broad skill refactoring, the initial `background/coordination.test.ts` fixture plus existing engine/ask-user tests passed 30 tests. Five real Unix transport identities shared two jobs in one actual Background engine (groups 4+1), without raising any constant or adding production runtime. Actual parent-mode ask-user calls returned two distinct nonanswers without UI; a third child fixture durably offered a result. One delivered shared attention led to reconciliation of all durable states. The fixture supplies checkpoint writes and acceptance judgment; it does not prove a model will perform them.

The fixture also exercises pre-registration exclusion, group-wide disconnect, independent coverage, exact incarnation replacement, membership exit and actual occupied-job capacity rejection. Existing engine tests cover simultaneous event queues/one-shot loss, overflow, setup loss, unknown handoff without retry, host attempt counts and interrupted state. Existing receipt tests cover restoration without replay. There is no new inbox, daemon or general task state engine.

## Bounded read-only reasoning scenarios

Give an independent reader the actual skill/shared references and fixture observations, without expected answers. No writes, external calls or live control are allowed. Retain its full response and compare next actions, proposed index changes, authority/correlation requirements and remaining uncertainty:

- Five independent owners; A and B have distinct pending human-only questions, C offers exact-revision evidence and explicit no-further-writes, D/E continue. Only A's shared signal arrived. Require all affected checkpoints read, two questions retained without modal wait, C accepted only on supplied valid evidence, no duplicate verification or budget copying.
- Replace coordinator after actual user takeover plus former relinquishment; A/B requests unanswered, C already accepted, one continuation submission uncertain, shared receipt has an attempted unknown handoff. Require retention and reconciliation, no duplicate prompt/owner, no reset, no completed-history reload. Corrupt ownership stops affected actions.
- Stale/unlabelled/cancelled answer or direct human intervention changes decision context. Require no fabricated approval or application; resolve current tuple with existing child. A valid answer records provenance and before-effect intent, registers attention within retained limits, then prompts that owner once and waits for matching application.
- C's offered evidence is missing, stale or failed; valid prior review covers only the old head. Require targeted qualification, honest incomplete status, not routine full redelivery for unchanged evidence. Accepted independent branches are not implicitly merged or proof of combined-state correctness.
- Ten routine wakes and unchanged status/progress. Require only mechanical coverage/accounting changes, zero no-change writes, retained adverse evidence and no duplicated child checklist. Capacity/overflow or registration gaps cannot be hidden by a worker-count default or a raised host constant.
- An existing serial stack requests status alongside new independent work. Require routing to its existing owner and records, predecessor/base/PR constraints intact, no automatic adoption/retirement/intermediate manager.

## Live validation recipe (requires separate authority)

The deterministic fixture is a regression floor, not proof of unlimited scalability. Live validation is **unrun unless explicitly authorized and recorded**. Obtain scoped authority for at least five disposable Herdr-managed Pi workers and a controlled coordinator handover, bounded session steering and optional cleanup. Require candidate source and primitives already available; installation/Stow/reload are separate approvals. Use no real publication or ticket mutations for this exercise.

1. Set an explicit shared deadline and wake ceiling, five fixed independent briefs and one coordinator; create exact-base worktrees using shared launch/readback/identity/attention-before-prompt ordering. Retain resources, receipts and actual execution confirmation.
2. Give A/B human-only choices, C a short independently verifiable result, D/E bounded independent tasks. Leave both questions unanswered. Verify the coordinator announces correlated ordinary-message questions once, continues D/E observation and accepts C's covered evidence without a modal wait or redundant checks.
3. Authorize handover, reconcile outgoing control/observers, then transfer. Verify two pending questions, C's accepted revision and every child owner survive; no duplicate prompts, new writers or allowance resets. Resolve A with a correctly labelled reply, give B a stale/cancelled reply, then a current answer. Inspect acknowledgment and honest provenance.
4. Exercise a membership replacement gap and one disconnect; verify whole-group reconciliation and unaffected coverage. Test uncertain submission using retained evidence, not deliberately replaying a prompt. Pause one assignment and require acknowledged quiescence before reporting paused.
5. Count snapshot bytes, coordinator writes by safe boundary, duplicate facts, model-authored arithmetic and actual reads/tool calls for status and recovery. Keep completed details by reference. Check zero no-change status writes and no routine progress transcription. Retain full traces privately and disclose any failure or unrun seam. Stop at bounds; clean up only with separate authorization.
