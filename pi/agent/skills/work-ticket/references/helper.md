# Ticket State Helper

Read this interface completely before invoking the helper. Follow [work-ticket](../SKILL.md); load [recovery](recovery.md), [publication](publication.md), or [settlement](settlement.md) before the corresponding operation. Paths to `scripts/ticket-state.js` are relative to the skill root, one directory above this reference.

Run `node <absolute-skill-path>/scripts/ticket-state.js` with one JSON request on stdin; never interpolate ticket prose into shell arguments. Responses are `{result: ...}` or `{error: ...}` with nonzero exit on failure. No user configuration or separate retained logs; state remains locally until explicitly authorized cleanup. State files are owner-only and bounded to 256 KiB. Locks/CAS/atomic rename protect cooperative users, not hostile processes or all power-loss cases.

All requests include absolute `cwd` and immutable `ticketId`. `status` reads the record; `snapshot` observes Git without updating evidence. Every mutation after initialization includes `runId`, `owner`, `expectedRevision`, and the stored `contract` baseline. Reread after writes. Never fabricate authorization, owner-release, check, or external-confirmation evidence: the helper validates consistency, not the truth of agent-supplied observations, and cannot intercept arbitrary shell/broker writes.

| Action              | Additional fields and contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `init`              | `identifier`, opaque `runId`/`owner`, `contract` (approved outcome/AC/scope baseline), `repository`, `targetBranch`, full `baseCommit`, optional `isolation` identity, `authorization: {operations, boundary, evidence}`, `plan: [{step, verification, status}]`. Operations: `implement`, explicitly authorized `commit`, `publish`, `settle`, `cancel`, `cleanup`; boundary: `local` or `pr` (requires commit + publish). Installs local exclusion and refuses existing attempts/other nonterminal checkout owners. |
| `checkpoint`        | `progress`, `nextAction`, optional updated `plan`, optional `status: active/waiting/blocked` and `blocker` when not active. No phase cursor.                                                                                                                                                                                                                                                                                                                                                                          |
| `reconcile`         | `observations` covering fresh ticket/files/Git/PR/check/owner state; `previousOwnerReleased: true` only for a proven owner takeover. Preserve run/count/plan.                                                                                                                                                                                                                                                                                                                                                         |
| `authorize`         | Explicit new `authorization` evidence and authorized `contract`; invalidates old scope evidence without resetting repair count. Does not reopen a completed delivery.                                                                                                                                                                                                                                                                                                                                                 |
| `evidence`          | `kind: verification/safety/ci`, current `fingerprint`, `passed`, `summary`; safety also requires `historyScanned`, `metadataScanned`, `publicContentChecked` all true and `metadataHash`; CI requires exact `head`.                                                                                                                                                                                                                                                                                                   |
| `review`            | Current `fingerprint`, `independent: true`, `complete`, `summary`, consolidated new `findings: [{id, blocking, category, evidence}]`, and `resolutions: [{id, disposition: fixed/not-applicable, evidence}]`. Retain existing open IDs rather than resubmitting them. Nonblockers remain visible.                                                                                                                                                                                                                     |
| `begin_repair`      | `repairPlan`; consumes one of two cycles durably before editing. Same review cannot consume twice.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `gate`              | `operation: commit/publish/promote/settle/cancel/cleanup`; checks stored authority and relevant evidence without writing or performing the operation.                                                                                                                                                                                                                                                                                                                                                                 |
| `external`          | Stable `key`, `operation` (publication/promotion/settlement/cancellation/cleanup or `implement` for a lifecycle/claim write), exact `intent`, `outcome: pending/confirmed`, `summary` of observations. Use operation names `publish`, `promote`, `settle`, `cancel`, `cleanup`, `implement`.                                                                                                                                                                                                                          |
| `publication`       | Reread `pr: {url, head, branch, base, open: true, draft: true}`, `confirmed: true`, matching `metadataHash`.                                                                                                                                                                                                                                                                                                                                                                                                          |
| `handoff`           | `summary`, confirmed `planeState: In Progress` for local; for PR, `planeState: Review`, reread `pr` with `draft: false`, `confirmed: true`.                                                                                                                                                                                                                                                                                                                                                                           |
| `settle` / `cancel` | Separately authorized and confirmed Plane `Done` / `Canceled`, `confirmed: true`; settlement of a PR requires `mergedHead`, cancellation requires `reason`.                                                                                                                                                                                                                                                                                                                                                           |

PR settlement gates and pending writes require `mergeConfirmed: true` and exact `mergedHead`. Cleanup gates and pending writes require `noLiveWriter`, `noUnpushedWork`, and `prDispositionKnown` all true plus matching `planeState: Done/Canceled`. Establish the fresh observations and prerequisites in the settlement procedure before supplying these fields; do not infer them from authority alone.
