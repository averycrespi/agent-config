# Parent observation accounting

Use `node <absolute-work-stack-path>/scripts/observation-state.js` with one bounded JSON request on stdin. This helper maintains parent observation accounting only; it never launches, prompts, qualifies delivery, advances a stack, or writes a child checkpoint. The parent Markdown snapshot references its sidecar rather than copying deadlines or counts.

Supply absolute repository `cwd`, stable `stackId`, `childId`, `owner` session UUID and exact child `incarnation`. State lives at `<git-common-dir>/pi-stack-checkpoints/<stackId>-<childId>.observation.json`. One parent owns it; immutable identity mismatches reject. Inspect `status` and existing resources before initialization. No live migration or automatic ownership transfer exists: reconcile the originating parent before resuming; stop on competing/unknown ownership rather than deleting records. For explicit transfer, `claim` requires `previousOwner`, `previousIncarnation`, actual `authority` and concrete absence/release `reference`, preserving allowances and uncertainties. An open watcher can transfer only with its unchanged child incarnation and must be reconciled before replacement; never strand an inactive predecessor's open intent or reset it during claim. Locks retain `owner.json`; prove that process absent before removing only a stale lock.

- `init`: actual `authority`; optional explicitly authorized finite `durationMs` and `wakeLimit` (defaults two hours and 30). Existing records reject reinitialization. For old Markdown accounting, explicitly supply `recovery: {reference, inactive: true, initialDeadline, deadline, attempts: [{id, unused, uncertain}]}` and original duration/ceiling. Retain uncertain reservations as charged and uncertain; no inferred zero usage or current-time reset.
- `prepare`: reserve one attempt atomically and return `allowance.watcher` with exact cycle/lifetime. Exhaustion or unresolved registration/handoff rejects without changes. This does not authorize another child or revoke its authority.
- Register one-shot Background with the same stable session filters, `retain: true`, returned cycle/lifetime, and `deadline_ms` when a deadline exists. First registration establishes the deadline from the actual host creation time; an unavailable first receipt conservatively anchors it to preparation. Reconcile the pre/post-ACK gap separately.
- `attach`: original host receipt plus concrete `reference`, or `receiptArtifact: {path, sha256}` from Background. Preserve exact originating tool-call/registration/incarnation correlation; an ID or display name alone proves nothing.
- `reconcile`: terminal original receipt/reference or artifact. Charges the reservation once; only proven unused suppressed/no-attention receipts release it. Pending/unknown delivery remains charged and unresolved. Receipt history remains referenced in the sidecar, not copied into Markdown.
- `recover`: `inactive: true` and concrete `reference` proving the original registration absent/inactive. Preserves the charged uncertain reservation, never retries a start.
- `resolve`: exact `attemptId` and concrete originating-owner `reference` resolving handoff uncertainty without replay. Consumption stays charged.
- `extend`: stable `id`, actual `authority`, `reference`, positive `additionalMs` and/or `additionalWakes`. Requires reconciled observation. Identical additions are idempotent; changes do not reset usage.
- `status`: current state and machine-computed remaining allowance, without changing the record. It is not a delivery/liveness verifier.

Keep child implementation, CI and repair state in the child checkpoint. Routine attention needs exact receipt accounting plus current child semantic state; full Git/PR/review/check qualification remains at boundaries, successor launch, recovery and inconsistency. Expiry stops parent observation and advancement only. Ordinary unfinished implementation, a commit or pending CI is not a release/reclaim boundary.
