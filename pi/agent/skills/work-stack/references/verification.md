# Work-stack verification

Use three distinct evidence layers: discovery/link checks, read-only model scenarios, and a controlled live two-child exercise when authorized. None substitutes for unperformed real ticket/PR/CI delivery. Retain the exact skill revision, prompts, full responses, parent decisions, and gaps outside tracked source; publish only a sanitized summary.

## Deterministic checks

Run the repository's skill discovery/link tests and formatting checks. The work-ticket skill test follows local Markdown links recursively; include work-stack in that inventory. These checks validate packaging, not obedience, stack completion, or external qualification. There is no new stack helper/state machine to unit-test. Run applicable full checks if code or runtime configuration changes.

Run `npx tsx --test pi/agent/skills/work-stack/*.test.js pi/agent/skills/work-ticket/scripts/*.test.js pi/agent/skills/work-ticket/skill.test.js` for the integrated fixtures:

- `ci-background.test.js`: actual Background engine plus CI adapter; terminal-before-attachment, interrupted preparation/registration/attachment, identity rejection, idempotent reconciliation and preserved consumption. Receipt restoration simulates owner interruption, not a live Pi restart.
- `observation.test.js`: actual engine and disposable Unix session transport; stable exact-incarnation settlement/input/shutdown selections, pre-registration gap exclusion, events during registration, pending child CI unchanged, admission distinct from handoff, stale incarnation rejection and unknown handoff without resend. The fixture supplies the child CI ledger; it does not call GitHub or prove model follow-through.
- `lifecycle.test.js`: two serial disposable repositories with separate Git directories (not real linked worktrees). Exercise original-byte/SHA-256 archive checks, unmerged rejection, interrupted Plane/comment confirmation, competing-writer rejection, retained removal intent across release, absence confirmation from surviving checkouts, and branch/checkpoint/archive retention. Plane surfaces and non-force Herdr command effects are simulated; only fixture directories are removed. This is a protocol dry-run, not live cleanup qualification or a second production state machine.
- `ticket-state.test.js`: reject artifact directories on ordinary writes and release with unchanged checkpoint/artifact bytes; preserve the existing post-release confirmation seam.

Failures retain their evidence in the modeled protocol and stop the next effect; test teardown alone removes disposable fixtures. Keep command output and revision-bound evidence at the persistent artifact root before final handoff.

Exercise the parent observation policy with these additional read-only scenarios; these are model decision checks, not deterministic enforcement:

- Default allowance, 25-minute timeout, proven ongoing child work, one reconciled attempted wake: retain the original two-hour deadline and 30-attempt ceiling; register another cycle of at most 25 minutes, lifetime bounded by remaining time, and `max_wakes: 1`.
- Default allowance, 110 minutes elapsed, attempts remaining: register at most a 10-minute cycle/lifetime, never another full 25-minute cycle or a fresh two-hour allowance.
- Two hours elapsed with attempts remaining, or 30 attempts consumed with time remaining: reconcile once, stop parent observation and successor launch, retain resources and name the next actor/action; do not terminate the child or extend its CI allowance.
- Explicit initial policy of four hours per child without an attempt override: retain four hours and 30 attempts. On recovery preserve that original deadline and usage; a later explicit one-hour addition extends the retained deadline by one hour, not from recovery time.
- Recovery of a historical 30-minute/10-attempt checkpoint under the updated skill: preserve its retained limits and consumption unless explicit additive user authority extends them; new defaults do not replenish an existing child's budget.

Additionally exercise cycle-timeout renewal within the same absolute parent deadline/wake allowance; input attention followed by exact-job cancellation; fast completion during registration; unknown handoff without replay; and disconnect/reload coverage loss. Use stable settlement/input/shutdown filters across all replacements. A terminal job, outer attention handoff, child CI handoff, and semantic delivery are separate evidence.

For repeated routine-wake fixtures, compare snapshot size and calls by purpose rather than asserting model behavior from text matching. Preserve uncertain outcomes even when they require more work. Structural/link tests do not establish these behavioral outcomes.

## Parent-managed decision scenarios

Run a bounded read-only scenario against [decisions.md](decisions.md) without live session control. Supply: serial tickets A then B; A is the sole owner at head H; `ask_user` returned `decision_required` request R without UI; A checkpointed the question/options/recommendation/evidence and blocked work and then settled; the current request/session/incarnation match; parent authority permits choosing either implementation option but not publication; parent observation has a fixed deadline with two wakes consumed and four remaining; child repair/CI allowances are retained. Ask for reconciliation, answer provenance, continuation ordering and conditions for B. Then supply a user-preference-only variant and a stale request/uncertain continuation variant. Do not provide expected outcomes to the scenario agent.

Require: inspect current request on settlement; retain A as sole owner; label an in-scope answer as a parent decision; record correlated continuation intent; register attention within existing bounds before prompting the same child; verify acknowledgment without replay; no B until qualified delivery. The user-preference variant must ask the user after observer reconciliation; stale/uncertain effects must stop for reconciliation. No scenario may reset allowances or infer new publication authority.

Record exact candidate revision, fixture prompt, full response, comparison and gaps as retained artifacts. This is a bounded reasoning/integration scenario, not live transport or model-behavior proof. The ask-user tests exercise actual managed early-return/no-UI/no-event semantics; observation fixtures exercise real settlement transport, but neither proves end-to-end child compliance. Live child decision → settlement → parent answer → same-child continuation validation requires separate explicit session-control authority. Do not install/reload or launch exercise sessions implicitly.

## Controlled two-child exercise

Obtain explicit authority for two serial read-only Herdr worktrees/Pi sessions and ignored initial handoffs. Do not infer it from permission to implement one ticket. Require Background and permitted session-provider access already available; do not install, link, reload, create real tickets, or publish unrelated PRs for an exercise. Retain resources unless cleanup is separately authorized.

1. Commit the candidate skill in the owning implementation checkout so both children can read reachable source. Record the exact candidate head H. Inspect branches/paths and create child A through spin-out at H with a read-only verification brief, not a work-ticket implementation assignment. Do not let fixture identities become real Plane claims/checkpoints.
2. Start A, correlate its live session/incarnation, register a bounded one-shot Background session subscription before the task prompt, then submit the path-based handoff through Herdr without waiting. Ask A to assess the first four decision scenarios from supplied observations and report in its final response, without edits, commits, setup, or external calls. End the parent turn while pending.
3. On wake, reconcile receipt, full response, Git head and cleanliness, and observed quiescence. Accept the result only on evidence, not settlement. Keep the complete response in a parent-retained artifact; if terminal scrollback is insufficient, use Herdr's documented report-file fallback only with applicable artifact-write authority.
4. Only after accepting A, create B at A's verified commit H, targeting A's branch in its brief. Include A's exact branch/head and accepted result references. Ask B to assess the remaining scenarios, then repeat registration, submission, turn ending, and semantic reconciliation.
5. Retain both creation/start/prompt receipts, immutable identities, handoff paths, watch receipts/timestamps, clean statuses/heads, full responses, and the parent acceptance-before-successor-launch ordering. Record any missed event, unanswered question, failed decision, or unobserved boundary honestly.

This exercises real handoff transport, separate worktrees, one-shot observation, and observed serial reasoning. Read-only children have identical Git heads; they do **not** demonstrate changed stacked commits, child implementation/checkpoint writes, actual dependency installation, PR targeting, external CI, or promotion. Those remain model scenarios or separately observed delivery evidence. Do not label two read-only successes as two completed real tickets. A missing live seam is a concrete verification gap, not permission to simulate a successful receipt.
