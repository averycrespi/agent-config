# Challenge

Stress-test a concrete proposed approach before implementation. Find material reasons to revise, investigate, or explicitly accept risk; do not produce dissent or a long critique for its own sake.

Read [the shared assessment procedure](references/protocol.md) completely and apply its **risk** lens. Challenge only claims whose failure would change whether to proceed, what to build, or how success is proven. Ground findings in concrete failure scenarios and evidence, and recommend a resolution. Validate strong proposals when supported; target the artifact, never the person.

Use `simplify` only when explicitly requested for a dedicated complexity assessment. Do not automatically add that assessment to every challenge. Use `review` for completed changes. Revise the target only within explicitly authorized scope.
