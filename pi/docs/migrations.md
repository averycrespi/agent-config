# Migration notes

Guidance for older installations. For current components, see the [Pi configuration reference](../README.md). Installation, Stow linking, settings changes and running-session reloads remain explicit user actions; repository edits do not perform them.

## Legacy workflow retirement

The `.design` lifecycle and its `architect`, `specify`, `plan`, `advance-plan`, and `create-jira-ticket` skills are retired. Use [direct authorized work or Plane delivery](../../README.md#working-with-the-agent). Existing local design artifacts remain historical context: verify their claims and re-scope unfinished work; never resume removed helpers or delete artifacts to restart delivery.

## Goal extension retirement

Goal's tool and `/goal*` commands are retired. During an explicitly authorized installation transition, remove explicit Goal load paths, `extension:goal` settings and `GOAL_*` overrides. Historical snapshots remain untouched and do not restore execution. Background supports optional explicitly authorized bounded continuation, not mandatory execution choreography.

## Observer retirement

Loop, Monitor and Session Watch are retired. These names, controls, events and receipt formats in this section describe **historical interfaces**, not callable guidance. [Background](../agent/extensions/background/README.md) is the sole supported session-bound observation/continuation primitive. Script, Code, scheduled tasks and unrelated tools remain supported.

### Controls, clocks and failures

- Historical Monitor `wait/notify` becomes Background `wait/wake`; evidence is limited to 4096 UTF-8 **bytes**, not characters. Explicit provider selection/global allowlisting replaces implicit Gateway availability. Eight calls, concurrency two and 30 seconds per evaluation are hard ceilings tightened by Script. No repeat-safe failure budget transfers: every evaluation failure terminates in v1. Diagnose failures rather than replay.
- Historical Session Watch discovery/start becomes `sessions.list()` plus typed event selections. Both sessions must load Background; old session incarnations and sockets are not adopted. A selected event grants attention only, never task completion or authority to answer for the user.
- Historical Loop limits/controls are not one-to-one aliases. Supply cycle timeout, total wall-clock lifetime, wake cap and delay explicitly. First delay starts at admission, subsequent delay after positively correlated awakened settlement. Lifetime includes waiting and agent work, unlike paused active-time accounting. Zero-delay and delays beyond 25 minutes have no identical timer-only mapping; choose an explicitly bounded supported cadence or stop for a material semantic change.
- Cancel and reconcile before requesting input. A later authorized fresh registration uses only remaining caller-owned allowance; it is not resume or extension. Retain consumed time/wakes and charge uncertain handoffs conservatively. If historical usage is unavailable, ask for a bounded recovery allowance instead of inventing zero. Budget additions require explicit authority and never reset consumption.
- Timeout requests attention without satisfying a condition. Distinguish condition, timeout, evaluation failure, coverage loss, cancellation, invalidation, budget exhaustion and unknown handoff. Reconcile receipt plus fresh semantic/external state; do not infer green CI from notification, runtime admission or settlement. Host `endedAt` records first observation stop; missing timing is conservatively accounted, not inferred from deadlines.

### Safe installation transition

1. Inventory existing load paths, `extension:loop`/`extension:monitor` settings, `LOOP_*`/`MONITOR_*` environment overrides and pending observers. Background has no corresponding settings/default migration. Do not weaken invalid policy or silently copy ceilings; explicitly allow only needed Script providers under existing authority.
2. Before any authorized reload/install, reconcile originating legacy receipts, current task state, cumulative allowances and pending notifications. If a legacy observer is still active or uncertain, resolve ownership through its originating session before replacement. Do not give two schedulers the same job. No automatic live cancellation, configuration linking or session reload occurs here.
3. Under explicit installation authority, remove retired extension paths/settings/overrides and load Background; changing repository source alone does not change an already-running session. Retired command names are unavailable afterward. The Background widget supplies one row per job; there are no legacy registrations to leave new orphaned rows.
4. Preserve `loop-state`, `loop-continuation`, `monitor:receipt-v1`, `session-watch:receipt-v1` and historical tool/session entries as history. They are not new Background receipts, success evidence, restoration requests or replay instructions. Never copy uncertain notifications into new jobs or delete session/socket files/unrelated state. Socket discovery does not clean up stale endpoints.
5. Register fresh work only after authority, exact identity, coverage gaps and remaining allowance are reconciled. Shutdown/reload/navigation restores Background receipts only, never execution or notification. Missing history is not proof of non-delivery; cancellation cannot retract Pi-owned messages.

## Ticket checkpoint and CI recovery

Current ticket delivery uses Background polling. Existing schema-v2 ledger names and historical receipts remain readable solely for recovery/accounting; new preparations are explicitly marked `backend: background`. Follow [work-ticket recovery](../agent/skills/work-ticket/references/recovery.md) and [helper receipt rules](../agent/skills/work-ticket/references/helper.md). Never mutate original historical bytes, refund consumed allowance or clear an uncertain registration merely to start again.
